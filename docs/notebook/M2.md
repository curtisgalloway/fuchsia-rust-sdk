`rules_rust` 0.69.0 (+ upstream patch), CIPD Rust toolchains for x64/arm64 Fuchsia and
host, and a `hello_rust` binary linking `libfdio.so` for both targets (I5, R2 link half,
D3, D4); see the plan's [M2 entry](../implementation-plan.md).

## 2026-09-27T18:46-07:00 — decision: Bazel 8.1.0, pinned in the repo, not in the lock
Plan/design say "matches sdk-samples/drivers": that is 8.1.0 (above). The link from a
release to a drivers commit is by date only, so it is not a lock field (resolve_pins
could not derive it from the release's artifacts). Pinned in the repo instead:
`.bazelversion` + `scripts/bazel.sha256` (GitHub's `.sha256` format), fetched by
`scripts/bazel` from the official GitHub release and checked. M14's regen can refresh
both files. Fallback if 8.1.0 fails with rules_rust 0.69.0: 8.5.1 (upstream's own).

## 2026-09-27T18:57-07:00 — decision: host links with the autodetected system C toolchain
Host linking selects `local_config_cc//:cc-compiler-k8` (`/usr/bin/gcc`). Upstream links
host Rust with its clang; here a host clang toolchain would need fuchsia_infra's
`host_clang_toolchain` or a hand-written cc toolchain. Not per-release, needed only for
host tools and proc macros, so accepted for M2 and recorded as a limitation.

## 2026-09-27T19:01-07:00 — attempt: first Fuchsia build; API level and rules_cc
`bazel build --config=fuchsia_x64 //examples/hello_rust` failed in analysis twice:
(1) `fuchsia_api_level` empty: rules_fuchsia's C++/package rules set it by transition
from `--default_fuchsia_api_level`, a bare `rust_binary` has none. Fixed with
`build:fuchsia --override_fuchsia_api_level=HEAD` (same level as the default).
(2) generated `@fuchsia_sdk//pkg/fdio` uses `cc_import(strip_include_prefix=…)`: no such
attribute. Bumped rules_cc 0.2.14 → 0.2.19 (fuchsia.git's pin): no change, because on
Bazel 8 rules_cc's `cc_import` is the native rule (`cc_compatibility_proxy`).

## 2026-09-27T19:01-07:00 — dead end: Bazel 8.1.0 (sdk-samples/drivers' version) cannot load this SDK
Bazel 8.1.0's native `cc_import` has no `strip_include_prefix`, and this release's
generated @fuchsia_sdk uses it for every prebuilt C library. So A2 fails as worded:
sdk-samples/drivers pins 8.1.0 only because it is still on SDK 32. Do not retry 8.1.0
for releases whose SDK emits that attribute.

## 2026-09-27T22:37-07:00 — surprise: the brief's regex walker misses bazel2gn files
`src/lib/diagnostics/log/rust/BUILD.gn` (and others generated by bazel2gn) writes
`deps = LIB_DEPS` with the list built at file level under `if (is_fuchsia)`; the brief's
regex only sees literal `deps = [...]` inside the target block, so it finds nothing
there. It also drops relative labels (`deps = [ "channel", "core" ]` in
`sdk/lib/driver/runtime/rust`) and `proc_macro_deps`.

## 2026-09-27T22:37-07:00 — decision: evaluate GN instead of matching it
New `scripts/gn_eval.py`: a tokenizer, parser and evaluator for the GN subset BUILD.gn
files use (assignments, `+=`/`-=`, `if`/`else`, lists, string `$var` interpolation, calls
with blocks as targets; imports and templates not run). Conditions are evaluated per
toolchain context (fuchsia: `is_fuchsia`, `current_os`, API level HEAD; host: linux,
PLATFORM); anything else is UNKNOWN and both branches are merged (list union), recorded as
"unknown". Build arguments get their `declare_args()` defaults from the file's imports.
`--mode all` (every condition UNKNOWN) reproduces the brief's upper-bound method.
Alternative rejected: patching the brief's regexes for variables (would still miss
conditions and relative labels).

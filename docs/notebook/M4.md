## 2026-09-27T21:18-07:00 — surprise: the IDK's version_history.json is key-sorted
The IDK copy has every object's keys sorted: `api_levels` runs `10…32, 4…9` and
`special_api_levels` `HEAD, NEXT, PLATFORM` (the source tree's `sdk/version_history.json`
is `4…32` and `NEXT, HEAD, PLATFORM`); it also adds a `status` field per level.
Upstream's `get_platform_version.py` run on the IDK copy fails its own assertion
(`Special API level "HEAD" is in the position expected to contain "NEXT"`) and would
otherwise emit levels in string order. So the port sorts numbered levels numerically
and checks special levels by name and `as_u32`, not by position. Content is otherwise
equal to the source file at `b5274053cc0f` (same levels, phases, ABI revisions).

## 2026-09-27T21:20-07:00 — decision: structure follows upstream
- Cfgs at the toolchain level: M2's `_API_LEVEL_RUSTC_FLAGS = []` becomes
  `get_rustc_api_level_flags()`, on all three toolchains (upstream sets it on host too).
  Wrappers add only `--cap-lints` (upstream `common.bzl`) and the lint config.
- Files mirror upstream's split: `rules/api_level.bzl` (`api_level.bzl`),
  `rules/rustc_api_level.bzl` (`rustc_api_level.bzl`), `toolchain/api_levels.bzl`
  (a repository rule porting `get_platform_version.py`, producing the
  `args.bzl` upstream reads from `@fuchsia_build_info`), `rules/rustc.bzl` (the three
  macros + `common.bzl`; one file because M5's rewrite targets `//rules:rustc.bzl`),
  `rules/lints/` (upstream's `rust_lint_config` targets: they carry rustc lints such as
  `unused_must_use = deny`, not only clippy).
- `select()` keys: `@fuchsia_sdk//constraints:api_level_<L>` (rules_fuchsia's flag,
  which `--override_fuchsia_api_level` sets) replace upstream's
  `//build/bazel/versioning:is_api_level_<L>`; PLATFORM, upstream's flag default, is
  `//conditions:default` (the flag unset, as on host).
- New file for the repository rule, so `toolchain/repositories.bzl` (which defines the
  3 GB IDK repo) is untouched and the IDK is not refetched.
- Golden test runs the same repository rule on pinned fixtures (the IDK copy and the
  source-tree copy of `version_history.json`), so a new release does not break it.
- Not ported: `generate_unit_tests` (R9 → M16; the attributes are accepted so upstream
  BUILD files load); no edition default (upstream has none and every upstream BUILD
  file sets `edition`), a deviation from the plan's step 2 wording.

## 2026-09-27T21:24-07:00 — decision: host toolchain gets the PLATFORM list directly
The host toolchain gets upstream's PLATFORM flags as a plain list (what upstream's
host code gets from its flag's default); the two Fuchsia toolchains get the
`select()` with no `//conditions:default`, so an unset level fails loudly (as
rules_fuchsia intends) and every level the flag accepts (27–32, NEXT, HEAD) has a key.
Consequence: proc macros and other exec-config code always build at PLATFORM.

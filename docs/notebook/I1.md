# I1 — SDK version → release revision

Goal: find a published, anonymously readable artifact that maps an SDK version
(`33.20260927.4.1`) to its `fuchsia.git` commit, and show it for one earlier
release too ([plan I1](../implementation-plan.md#i1--sdk-version--release-revision),
design §2.3 A1 and §8.1 I1).
Verdict record: [evidence/I1.md](../evidence/I1.md).

## 2026-09-27T17:54-07:00 — surprise: CIPD `git_revision` is the integration commit, not `fuchsia.git`

is the `integration` entry (the private integration repo, `releases/canary`) in
the product builds' `source_manifest.json`, not a `fuchsia.git` commit. So

"no such tag"). CIPD alone cannot give the `fuchsia.git` revision.

## 2026-09-27T17:54-07:00 — attempt: lookup for two releases
Scratch script (`lookup.sh`, copied into the evidence) chains: `product_bundles.json` →
each build's `source_manifest.json` → CIPD IDK instance `git_revision`, asserting
all builds agree and match the IDK's integration commit.
`33.20260927.4.1` → `b5274053cc0f1ba03cd0902a3da575ac9c31c152` (8 builds).
`33.20260919.6.1` → `71dec18ae96814c5b5061e51d3b626be82c63ba4` (9 builds; integration
`f969c555…`, the value `fuchsia-cloud-dev` pins). Next: tie the IDK's own content to
the commit, since the link so far is via the shared integration commit.

## 2026-09-27T17:58-07:00 — attempt: IDK content cross-check (FIDL blob ids)
Streamed each release's IDK once more, extracting only `fidl/` (7 MB, about 90 s
per release), then compared `git hash-object` of every IDK `.fidl` with the `.fidl`
blob ids in the commit's tree (blobless shallow fetch of `main` since 2026-09-18,
9 MB). `33.20260927.4.1` (728 files): 0 missing at `b5274053`, 1 missing at
`bb845d9^` (the last FIDL change before it), 15 at `71dec18`.
`33.20260919.6.1` (725 files): 0 missing at `71dec18`; 1 missing at `e8e7ecb^`
and at `567cf03` (the FIDL changes either side of it); 12 at `b5274053`.
So each IDK's content is consistent with its looked-up commit and excludes the other
release's. The bound is a FIDL-change window, not an exact commit; the exact commit
comes from `source_manifest.json`.

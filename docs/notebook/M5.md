## 2026-09-27T21:45-07:00 — decision: crates.io subset here; `zx` deferred to M6
By inspection at `b5274053cc0f`:
- `zx-types` itself needs `zerocopy` (`crate_features = ["zerocopy"]`, derive macros),
  so M5 cannot avoid crates.io entirely. The closure of upstream's own
  crate_universe BUILD files from `zerocopy` is six crates (`zerocopy`,
  `zerocopy-derive`, `proc-macro2`, `quote`, `syn` 2.0.119, `unicode-ident`), all plain
  crates.io crates whose Cargo.lock checksum equals the `.cargo-checksum.json` package
  hash of fuchsia.git's copy.
- `zx` adds `libc` (upstream uses `forks/libc-0.2.189`, a fork) and `bstr`, whose BUILD
  file depends on `ask2patch/memchr` (a `[patch.crates-io]` crate); upstream's unified
  `bitflags` features also pull `serde_core`. Patched crates "as local repositories
  from `third_party/rust_crates/`" are M6's scope and a design choice (build-time git is
  what D6 rejected; committing their sources is new). So `zx` waits for M6.
- Mechanism for the subset: no local crate_universe run. Upstream already ran
  crate_universe over the release's Cargo.toml/Cargo.lock; `regen.py` takes those
  generated per-crate `BUILD.bazel` files, rewrites their labels, and commits them in
  `third_party/crates/` with a list of crates.io URLs and the release Cargo.lock's
  SHA-256 checksums (Cargo.lock itself checked against the lock's `cargo_lock_sha256`).
  A repository rule downloads each `.crate` by that checksum (C1/C3), so the build needs
  no resolution step. M6 may replace this with its own crate_universe run.
- `zx-status` and `zx-status-ext` (only `zx-types` below them, both with upstream Bazel)
  come along now, so M6 adds only `zx` and its crates.

## 2026-09-27T21:59-07:00 — decision: license placement, patch scope, orphan inputs
- **LICENSE (acceptance 5).** No upstream crate directory has a `LICENSE`; fuchsia.git's
  root `LICENSE` (and `PATENTS`) cover them, and every file header says "found in the
  LICENSE file" at the root. `vendor/fuchsia/` mirrors that root (D9), so regen.py copies
  both there, byte for byte, instead of adding a non-upstream `LICENSE` to each crate
  directory. Per-crate `METADATA.textproto` files are carried as they are. `REUSE.toml`
  annotates `vendor/fuchsia/**` as BSD-3-Clause, the Fuchsia Authors.
- **Patches** are fuchsia.git-root-relative (`git apply` in the staging
  `vendor/fuchsia/`), and one under `patches/fuchsia/<path>/` may touch only `<path>/`
  (checked with `git apply --numstat` first), so a patch's location says what it changes.
- **Orphans fail.** An overlay or patch for a path not in `vendor/crates.txt`, or an
  overlay for a crate listed `upstream`, stops the run (it would otherwise be silently
  ignored).
- Added `tests/vendor`: M4's `cap_lints_test` on each vendored crate (`allow`), so the
  `vendored = True` rewrite is checked in Bazel as well as in pytest.

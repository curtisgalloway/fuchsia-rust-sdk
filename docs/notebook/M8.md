# M8 — FIDL Rust binding rule (M8a: the `rust` flavor)

Goal: [M8](../implementation-plan.md): `rules/fidl_rust.bzl` generating FIDL Rust bindings
from IDK FIDL sources with the IDK's `fidlc`, the FIDL runtime crates vendored, and
bindings for every FIDL library in pilot 1's closure compiling for both Fuchsia targets.
Split before starting (see the sizing entry): this chapter covers M8a; M8b gets its own.
Verdict record: [M8 evidence](../evidence/M8.md)

## 2026-09-28T02:06-07:00 — decision: split into M8a (`rust`) and M8b (`rust_next`)
From `pilot1.json` (reversing `used_by`): the bindings' in-tree runtime closure is 26
crates, 5 already vendored (`zx*`, M5), so 21 new: over the plan's ~10 threshold.
`rust`/`rust_common` alone need 18 (13 new): `fidl`, `rust_constants`, `fuchsia-async`,
`fuchsia-async-macro`, `fuchsia-sync`, plus 8 driver-runtime crates (`fidl_driver`,
`fdf`, `fdf_channel`, `fdf_core`, `fdf_sys`, `libasync*`) that only the two
`contains_drivers` libraries pull in, and which have no upstream `BUILD.bazel` (M9's
set). `rust_next` adds `fidl_next*` (5) + `fuchsia-loom` + `fdf_fidl`.
The generated driver-transport code is all `#[cfg(feature = "driver")]`
(`driver_protocol.tmpl`), and GN passes `contains_drivers` to the `rust` flavor only with
`enable_rust_drivers` and never on host; upstream's Bazel rule has the driver deps
commented out (fxbug.dev/503359085). So M8a = the IR step, `rust` + `rust_common` (+ the
trivial `rust_flex`, which is only `pub use` of the `rust` crate), the 5 non-driver
runtime crates, bindings for all 23 libraries built without the `driver` feature; M8b =
`rust_next`/`rust_next_common` + the driver transport for both flavors (feature + the
driver-runtime crates).

## 2026-09-28T02:11-07:00 — decision: FIDL libraries go through `regen.py` like crates
`vendor/crates.txt` gets a third mode, `idk`: upstream's `BUILD.bazel` rewritten
(`fidl_library` → the overlay's `//rules:fidl.bzl`), `.fidl` sources taken from the IDK
(`@fuchsia_sdk//fidl/<lib>:<file>`, D7), nothing else copied. Labels then line up with
what vendored crates name (`//sdk/fidl/fuchsia.io:fuchsia.io_rust` →
`//vendor/fuchsia/sdk/fidl/...`), and a release bump regenerates the declarations.
`fuchsia.sys2` (not in the IDK, `category = "host_tool"`) is listed `upstream`: its
`.fidl` files come from fuchsia.git at the revision, compiled by the IDK's `fidlc` (plan
step 5's second option; no trim of `cm_rust`, which is M9's).
Rejected: a repository rule over the IDK's `meta.json` (has no `contains_drivers` /
`enable_rust_*`); hand-written declarations (manual edits per release, R10).

## 2026-09-28T02:11-07:00 — decision: FIDL runtime crates are Fuchsia-only; host branches trimmed by patches
`fidl` and `fuchsia-async` build for host with `//src/lib/fuchsia-emulated-handle`,
which needs `tokio` (a fork, `forks/tokio-1.53.1`, sources only in fuchsia.git) and
`futures-lite`; `fuchsia-sync` on host needs `parking_lot(_core)`; their test deps add
`assert_matches`, `futures-test`; `fuchsia-sync` names `forks/tracing-mutex`. None is in
pilot 1's closure (every one of these crates has context `fuchsia` only), and pytest
requires the generated crate set to equal the closure's 121. So: patches under
`patches/fuchsia/<crate>/` (applied after the rewrite, before regen.py collects crate
roots) drop the host branches and test deps and add `target_compatible_with =
["@platforms//os:fuchsia"]`. For the rewrite to reach the patch step, an unlisted
in-tree label inside a `//conditions:default` branch is mapped provisionally and must be
gone after the patches (checked, file:line). Consequence for the host-level question:
host bindings can be generated but not compiled with pilot 1's closure (below).

## 2026-09-28T02:24-07:00 — decision: host FIDL bindings at PLATFORM, as upstream (tested)
Upstream (`fidl_ir.bzl`, `fidl_library.gni`) compiles IR at the target API level and
expands PLATFORM to `runtime_supported_api_levels`; host code is at PLATFORM. The overlay
does the same, so host bindings and host cfgs agree (the backlog's first option; host
cfgs stay at PLATFORM). Tests: host `contains_test` finds `fuchsia.io/NodeInfoDeprecated`
(`removed=32`) in the host IR; on Fuchsia, `tests/fidl:api_level_consistency` imports
`fidl_fuchsia_io::*` and a stand-in `NodeInfoDeprecated` by glob, which is ambiguous
(E0659) if the bindings have the type. Negative check: forcing PLATFORM on Fuchsia gives
exactly that E0659 (excerpt in the evidence). Host bindings are generated but not compiled: the `rust` runtime is
Fuchsia-only in pilot 1's closure (previous decision).

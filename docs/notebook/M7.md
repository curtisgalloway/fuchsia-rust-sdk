# M7 — FIDL generators as Bazel host tools

Goal: [M7](../implementation-plan.md#m7--fidl-generators-as-bazel-host-tools): both FIDL
generators runnable as Bazel host tools. `fidlgen_rust_next` fetched by a lock pin that
`resolve_pins.py` resolves per release; `fidlgen_rust` built from vendored source with
rules_go and a pinned Go SDK (route decided after I2).
Verdict record: [M7 evidence](../evidence/M7.md)

## 2026-09-28T01:16-07:00 — decision: what the generators need besides themselves, and the golden test
Upstream runs both with `--rustfmt <toolchain>/bin/rustfmt --rustfmt-config //rustfmt.toml`
(`build/rust/fidl_rust.gni`, `fidl_rust_next.gni`), and `fidlgen_rust_next` also with
`--config tools/fidl/fidlgen_rust_next/configs/{fuchsia,common}.json` (and
`--common-lib fidl_next_common_<lib>`; `fidlgen_rust`: `--use_common=fidl_<lib>_common` /
`--common=true`). M8 needs the same, so regen.py now vendors `rustfmt.toml` (a root file,
exported from `vendor/fuchsia/BUILD.bazel`) and `tools/fidl/fidlgen_rust_next/configs`
(an overlay BUILD exporting the JSON). For "diffs cleanly against upstream": upstream's
golden tests run each generator on fidlc's IR goldens (`tools/fidl/fidlc/goldens/<n>.json.golden`)
and compare with `tools/fidl/<gen>/goldens/<n>[_common].rs.golden`. The overlay does the
same with skylib `diff_test` for 5 libraries (bits, enum, handles, protocols, struct): the
`fidlgen_rust` goldens are already vendored; the 5 IR goldens and 10 `fidlgen_rust_next`
goldens (~0.7 MB) are copied by hand into `tests/fidlgen/testdata` (as M4 did for its
fixtures), not all 112 fidlc goldens through regen.py.

`MODULE.bazel.lock` grew by ~3,200 lines. Most were extension results written by my own

crate_universe's `cu_nr`); removing them and re-running the three builds and
`bazel test //...` re-added none, so they are dropped. What the builds do write: 27

SHA-256s. rules_go's own `go_sdk.from_file(go_default_sdk)` (never selected: the root's
`wrap` comes first) makes its extension fetch `https://go.dev/dl/?mode=json&include=all`
when the facts lack its version, with `allow_fail = True`, and stores the answer in the
lockfile "for airgapped builds". Checked in a scratch output base with go.dev blocked
(downloader config `block *` + BCR, github.com, CIPD, GCS, static.crates.io): with the
facts and `--lockfile_mode=error`, `query deps(//vendor/fuchsia/tools/fidl/fidlgen_rust)`
evaluates `go_sdk` and exits 0 (facts used, no request); with `--lockfile_mode=off` (no
facts) it also exits 0 (the blocked fetch is tolerated). No Go SDK archive or module is
ever downloaded from go.dev.

## 2026-09-28T07:38-07:00 — surprise: an in-tree pure-Rust driver binds through the same spec shape
`composite show 00_04_0`: driver `fuchsia-boot:///virtio-gpu-display#meta/virtio-gpu-display.cm`,
parent 0 `pci (Primary)` = `PCI0.bus.00_04_0`, parent 1 `acpi` =
`acpi._SB_.PCI0.S20_.pt`, composite node `PCI0.bus.00_04_0.00_04_0`. So the parent
names the lead uses are the ones the bus's specs carry, and a Rust driver's composite
binding path already works on this image.

## 2026-09-28T07:39-07:00 — decision: keep the lead's rule as is, and check it in the build
Kept `using fuchsia.pci;` although the rule names only keys from the built-in
`fuchsia` library: it is the rule already seen binding (`fuchsia-cloud-dev`), and
`bindc -l` accepts it. Added the `bindc test` spec to the pilot as
`meta/simple_rust_bind_test.json` with `rules_fuchsia`'s own
`fuchsia_driver_bind_bytecode_test` (`bindc test --lint`), so the match against the
emulator's spec properties is re-checked by `bazel test` (Fuchsia configs), not only
recorded. Alternative (scratch-only check) rejected: M11/G1 would have no regression
check that the rule still matches after a release bump.

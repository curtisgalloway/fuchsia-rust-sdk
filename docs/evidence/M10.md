### Deviations from the entry and decisions (see the notebook)

- **`libdriver_runtime.so` is packaged** (notebook 06:45; the recovered draft excluded
  it). All three pure-Rust drivers in `core.x64` ship `lib/libdriver_runtime.so`, and
  `fuchsia_cc_driver` packages it; the C++ drivers that do not ship it rely on the driver
  host's copy. The rule packages every shared library in the cdylib's runfiles at `lib/`
  (as `fuchsia_cc` does); only `libc.so` (the soname of `lib/ld.so.1`) and `libzircon.so`
  (the vDSO) are expected unpackaged.
- **Soname.** The `core.x64` Rust drivers have `DT_SONAME` = `<output_name>.so` (GN; and
  `cc_shared_library` does the same for `fuchsia_cc_driver`); rules_rust sets none, so the
  rule links with `-Wl,-soname=<output_name>.so` and the ELF test checks it.
- **Restricted-symbols check on.** `fuchsia_cc_driver` leaves it commented out
  (TODO(352586714)); `fuchsia_rust_driver` runs it as `fuchsia_cc` does when
  `restricted_symbols` is set: a build action whose output (a checked copy of the
  library) is the file that gets packaged, so no package skips it.
- **`fidl` visibility: patch `0002`.** Upstream Bazel limits `src/lib/fidl/rust/fidl` to
  its listed packages; GN's visibility is `//*` (the `@bazel2gn:raw_overwrite` comment).
  `patches/fuchsia/src/lib/fidl/rust/fidl/0002-visible-to-overlay-drivers.patch` adds
  `//drivers:__subpackages__` (backlog item "`fidl` is visible only to upstream's
  packages"). Nothing else the pilot names directly is restricted.
- **`.bazelrc`: the Fuchsia configs set `--cpu` and the package transition's options**
  (notebook 06:59). rules_fuchsia's `fuchsia_package` transition takes the CPU from
  `--cpu`, not `--platforms`: under `--config=fuchsia_arm64`, `:pkg` held x64 binaries
  (the first arm64 test run passed on them). The transition also adds `--copt=--debug`,
  `--copt=-ffuchsia-api-level=<u32>` and `--strip=never`, so each package build rebuilt
  the Rust closure in a `-ST-` output directory (0.47 GiB each). The configs now set
  `--cpu=x86_64` / `--cpu=aarch64` and those three options (HEAD = 4292870144,
  `special_api_levels.HEAD.as_u32` in the IDK's `version_history.json`; checked by
  `//tests/api_level:bazelrc_head_u32_test` against `@fuchsia_sdk//:api_version.bzl`, the
  table rules_fuchsia generates from it and the transition reads, and by
  `tests/test_bazelrc.py` against the pinned copy of the IDK file), making the transition a no-op: packages are built in the config's
  own `bazel-bin`. The copts reach only C code (11 objects, `fit-promise`); Rust actions
  were cache hits. The ELF test now checks every packaged file's machine.
- **Placeholder bind rule** (`drivers/simple_rust/meta/placeholder.bind`): upstream's rule
  names `gizmo.example`, a bind library outside the IDK. It uses `fuchsia.test` only and
  matches no `core.x64` node; the bytecode keeps GN's name `rust.bindbc`, which the
  manifest names. I3 replaces it.
- **The bind library's Rust crate: `rules/bind_rust.bzl`** (`fuchsia_bind_rust_library`,
  GN's `_bind_library_rust`: `bindc generate-rust --lint`, crate `bind_<name>`, edition
  2024, lint config `deny_unused_results`), with the IDK's `fuchsia.test` crate in a
  shared `//drivers/bind` package named as GN names it (`fuchsia.test_rust`).
- **The manifest check reads the packaged `.cm`.** cmc records the manifest's source and
  include files in the compiled manifest; the test requires `…/syslog/client.shard.cml`
  and `…/inspect/client.shard.cml` there, and the `/svc/fuchsia.logger.LogSink` and
  `/svc/fuchsia.inspect.InspectSink` uses the shards add.
- **Package tests are Fuchsia-only** (`target_compatible_with`): through `:pkg`'s
  transition a host build would otherwise build the driver for x64. The "Binary checks"
  row of the plan's project checks therefore runs `bazel test //...` under both Fuchsia
  configs.
- **Not translated from `BUILD.gn`:** `with_unit_tests`, `test_deps`, the realm test and
  the unit-test packages (M16; the rule accepts both attributes and generates nothing);
  `info = "meta/component-info.json"` (no Bazel counterpart); the DML (`meta/rust-driver.dml`,
  from which GN generates the same `.cml` that is checked in); GN's
  `verify_shared_libraries` and `assert_no_deps` checks of `fuchsia_driver_package`;
  `fuchsia_cc_driver`'s `@fuchsia_sdk//clang:sanitizer_resources` data (only sanitizer
  variants need it; the overlay builds none). `testonly` is not forwarded to the wrapper
  rule `<name>` (only to the cdylib) — needed when M16 builds test drivers.

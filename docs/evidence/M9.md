### The overlays

Each header records the `BUILD.gn` blob it translates. The same GN → Bazel mapping,
stated in every header:

- target name, crate name (GN `name`/`crate_name`), edition, version, `sources`
  (→ `srcs`), `deps`: unchanged; in-tree deps → `//vendor/fuchsia/<path>`,
  `//third_party/rust_crates:<c>` → `@rust_crates//vendor:<c>`;
- C deps → the IDK's prebuilt libraries: `//sdk/lib/async` → `@fuchsia_sdk//pkg/async`
  (a `cc_library` over `ops.c`, as GN's `zx_library`), `//sdk/lib/async-default` →
  `pkg/async-default`, `//src/devices/lib/driver:driver_runtime` (GN's link stub) and
  `//src/devices/bin/driver_runtime` → `pkg/driver_runtime_shared_lib` (a `cc_import`
  of `libdriver_runtime.so` with both `interface_library` and `shared_library`, deps
  `fdio`, `svc`, `trace-engine`; `pkg/async-default` likewise for
  `libasync-default.so`; whether a driver package ships them is M10's question);
- GN visibility `//<dir>/*` → `//vendor/fuchsia/<dir>:__subpackages__`, `:*` and
  `//<dir>:*` → `…:__pkg__`; none → public;
- `configs += clippy_warn_all` → `lint_config = "//rules/lints:clippy_warn_all"`;
- `vendored = True` (`--cap-lints=allow`), as `regen.py` adds to upstream's rules (and
  requires of overlays);
- `target_compatible_with = ["@platforms//os:fuchsia"]`: pilot 1's closure reaches each
  only in the fuchsia context, and their C deps are Fuchsia-only;
- `with_unit_tests` kept; `test_deps`, `rustc_test`, the test FIDL libraries,
  `rustc_bindgen_golden` and package targets are comments (M16).

## Findings for later milestones (also in the plan backlog)

- **Macro-declared targets are visible to `//rules` code** (corrected after review
  finding 1). Every crate declared with `rustc_library` (a symbolic macro defined in
  `//rules`) is visible to an edge written in `//rules` code whatever its own
  visibility; such an edge ignores the `fidl_driver` restriction upstream states. Only
  top-level targets (the `fidl_next` alias) need `//rules:__pkg__` entries. M10: the
  overlay's own driver packages are ordinary BUILD files, so they do need entries (or
  public crates) for what they name directly.
- **Runtime shared libraries in packages (M10).** `pkg/driver_runtime_shared_lib` and
  `pkg/async-default` carry `shared_library` as well as `interface_library`. M10 checks
  whether packaging a driver pulls in `libdriver_runtime.so` / `libasync-default.so` and
  excludes them if the driver host provides them (upstream drivers link the stub).
- **bindgen goldens** for `libasync_sys`/`fdf_sys` are not checked (M16).
- **M9b/M9c:** `num-derive` and `paste` have their first exec-config builds in M9b (only

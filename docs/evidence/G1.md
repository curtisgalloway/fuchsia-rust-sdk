## Deviations

- **The fresh container was simulated by deleting caches.** A new container was not
  available. Bazel's output base, repository cache and install, the overlay's caches,
  the emulator state and uv's cache were deleted, and the repository was cloned from
  GitHub. Not reset: pre-installed tools (uv, Python, git, system packages), `~/.config`
  (it held no overlay profile) and the kernel page cache. What these could hide is
  limited to host-tool assumptions. The README's host contract lists those, and M3
  probed them.
- **The disk budget was not measured in a clean filesystem.** The container held other
  data (earlier runs' scratch directories, other repositories). `disk_report.py` counts
  only the overlay's buckets, so the budget comparison is unaffected. The "free" column is
  this container's.
- **Check 4 `setup` had the IDK already.** The builds of check 3 fetched it, so `setup`
  downloaded only the bundle, 23 s. The replay says "first time only", and running the
  build first is the order in which the plan lists the checks.
- **Timing used `date +%s` stamps.** `/usr/bin/time` is not installed; the first x64
  launch under it exited 127 before Bazel started, and the cold build ran again from
  the same empty state.

## Findings for later milestones

- **M12 / later drivers:** the guide's recipe is the path for pilot 2 too. For each
  dependency outside pilot 1's closure it needs the `vendor/crates.txt` /
  `vendor/crates_io.txt` / closure update, which is manual until M14. The guide says so
  under "Limits".
- **M14 (R12):** the counts above are the first closure-report data (69 / 121 / 23). The
  report should also record cold-build time and peak disk; they are cheap to capture.
- **Emulator workflow:** registrations for one node are first-come. A second driver for
  the same spec registers without error but does not bind, and ffx reports only "No new
  nodes were bound". A `scripts/emu driver` check that fails when the spec is already
  bound by another URL would turn that into an error (backlog).
- **`bind_test` is Fuchsia-only by toolchain resolution,** not by an explicit
  `target_compatible_with`. Host `//...` skips it silently, as it does the ELF and
  manifest tests (the M6b backlog item on incompatible targets).
- **ffx noise:** besides M11's ssh retry message, `ffx log` prints `WARN: missing
  authentication for symbol servers` first. A replay script that treats stderr or `WARN`
  lines as failures would trip on it.

## Limitations

- The gate ran in a simulated fresh container (above), in one run. Cold-build times vary
  with network and CPU.
- The binding test covers x64 on the emulator only. arm64 is built and tested but first
  loads on the VIM3 (M13).

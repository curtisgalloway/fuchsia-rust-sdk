## Milestone definition

### The split (before starting)

The plan's M8 says to split before starting "if the runtime crate list in `pilot1.json`
is longer than about 10 crates". Inverting `pilot1.json`'s `used_by`, the bindings'
in-tree runtime closure is 26 crates, 5 already vendored (`zx*`), so 21 new:

| Set | New crates | Upstream `BUILD.bazel` |
|---|---|---|
| `rust`/`rust_common`, no driver transport (M8a) | `fidl`, `rust_constants`, `fuchsia-async`, `fuchsia-async-macro`, `fuchsia-sync` | all 5 |
| `rust_next`/`rust_next_common`, no driver transport | `fidl_next`, `fidl_next_bind`, `fidl_next_codec`, `fidl_next_protocol`, `fidl_next_util`, `fuchsia-loom` | all 6 |
| driver transport (`rust_next` via `fdf_fidl`) | `fdf_fidl`, `fdf_channel`, `fdf_core`, `fdf_sys`, `libasync`, `libasync_dispatcher`, `libasync_sys`, `libasync_fidl` | none |
| driver transport (`rust`) | `fidl_driver`, `fdf` | none |

So M8a is the `rust` flavor (with `rust_common` and the trivial `rust_flex`) and its 5
crates; M8b (new plan entry) is `rust_next`. After the review the orchestrator decided
that the driver transport (the last two rows) moves to M9, which already vendors those
crates, together with the two driver libraries' `rust_next` crates; M8b covers the 17
other libraries. The orchestrator accepted this split in advance. The driver transport is
deferred in M8a exactly as upstream's own Bazel rule defers it (fxbug.dev/503359085):
the generated driver code is all `#[cfg(feature = "driver")]`, so the `rust` crates
compile without the feature, and GN passes `contains_drivers` to the `rust` flavor only
with `enable_rust_drivers` (only `fuchsia.driver.framework` sets it) and never on host.

### How a binding is made

`regen.py` copies upstream's `sdk/fidl/<lib>/BUILD.bazel` (a `fidl_library(...)`),
rewriting its load to `//rules:fidl.bzl`, its deps to `//vendor/fuchsia/sdk/fidl/<dep>`
(`//zircon/vdso/zx` likewise), and, in `idk` mode, each `srcs` entry to
`@fuchsia_sdk//fidl/<lib>:<file>` (the IDK flattens a library's files into
`fidl/<lib>/`). The macro then declares, in `//vendor/fuchsia/sdk/fidl/<lib>`:

| Target | What |
|---|---|
| `<lib>` | IR `<lib>.fidl.json`: `fidlc --json … --name <lib> --versioned <v> --available fuchsia:<level> --files <dep files>… --files <own files>` (deps in dependency order) |
| `<lib>_rust`, crate `fidl_<lib_>` | `fidlgen_rust … --use_common=fidl_<lib_>_common [--include-drivers]`, edition 2018; deps `zx-status`, `fidl`, `bitflags`, `futures`, each FIDL dep's `_rust` (zx → `zx-types`), `:<lib>_rust_common`, `zx` on Fuchsia |
| `<lib>_rust_common`, crate `fidl_<lib_>_common` | `fidlgen_rust … --common`; each FIDL dep's `_rust_common` |
| `<lib>_rust_flex`, crate `flex_<lib_>` | `pub use fidl_<lib_>::*;`, edition 2024 |

`<level>`: rules_fuchsia's API level on Fuchsia (HEAD in the overlay's configs); on host
PLATFORM, which upstream (`fidl_ir.bzl`, `fidl_library.gni`) expands to
`runtime_supported_api_levels` (`27,28,29,30,31,32,NEXT,HEAD` for this IDK). `<v>`: the
ported `_get_fidlc_versioned_arg` (`fuchsia` for stable libraries, `fuchsia:HEAD` for
`fuchsia.power.broker`, which is unstable).

**Naming rules (criterion 2).** `rust` flavor (`fidl_rust.gni`): `fidl_<lib_>`,
`fidl_<lib_>_common`, `fdomain_<lib_>`, `flex_<lib_>`, with `<lib_>` the library name with
`.` → `_`. `rust_next` flavor (`fidl_rust_next.gni`, for M8b): crate
`${prefix}_next${common}_<lib_>` with prefix `fidl` (or `fdomain`) and `_common` for the
common crate, i.e. `fidl_next_fuchsia_io`, `fidl_next_common_fuchsia_io`; GN targets
`<lib>_rust_next`, `<lib>_rust_next_common` (groups over `…_internal`); the regular crate
gets `--common-lib fidl_next_common_<lib_>`.

## Deviations from the plan text

- **Split** into M8a/M8b (above; accepted in advance). The plan's M8 heading became
  M8a's; M8b is new. `rust_flex` (1 library) is in M8a: it is only `pub use` of the
  `rust` crate. The status table's M9 row now depends on M8b.
- **FIDL libraries through `regen.py`** (not in the plan's steps): upstream's
  `sdk/fidl/<lib>/BUILD.bazel` files are vendored and rewritten like crates; `idk` mode
  keeps D7 (IDK sources, IDK `fidlc`). Labels then match what vendored crates name.
- **`rules/fidl.bzl`** holds the IR and the macro (upstream's `fidl_library.bzl`,
  `fidl_ir.bzl`); `rules/fidl_rust.bzl` the Rust flavors (design §4.1 names only the
  latter). fidl-lint and the IR schema validation are not run; the C++/HLCPP/Banjo/
  Zither backends, IDK atoms and compatibility tests are not built (arguments accepted
  and ignored).
- **GN parity over upstream's Bazel rule** where they differ: zx → `zx-types` crate;
  GN's lints (`//rules/lints:fidl_rust`: `unused_crate_dependencies` allow,
  `unused_results` deny, no clippy); `--include-drivers` only on Fuchsia and only with
  `enable_rust_drivers`.
- **`rustc_proc_macro` host-only by default** (`rules/rustc.bzl`, an M4 file): needed for
  `bazel build --config=fuchsia_* //...` with in-tree proc macros; generic for M9's.
- **`regen.py` fix:** `generate_crates` left `crates_json` unset when no crate is named
  (`UnboundLocalError`, only reachable from a test tree).
- **`fuchsia.sys2`'s FIDL sources come from fuchsia.git** at the release revision, not
  the IDK (D7 says IDK sources; the IDK does not have the library). Authorised by the
  plan's step 5, and consistent with C1 (anonymous git) and C3 (the release revision);
  the compiler is still the IDK's `fidlc`. The orchestrator amends design D7/R5 after
  the checkpoint.
- **Patches, not overlays,** make three upstream crates Fuchsia-only. Design §4.2
  allows patches for trims; each patch states its reason.
